## 4. SecDevOps

### 4.1 CI 파이프라인

모든 PR에서 자동 실행합니다. **하나라도 실패하면 머지 불가.**

```
PR 생성
  ├─ gitleaks           시크릿 하드코딩 검출        → 실패 시 즉시 중단
  ├─ 의존성 취약점 스캔    npm audit (FE) / BE 스캐너는 배포 전 추가
  ├─ 품질 검증           ./gradlew check (BE) / eslint (FE)
  ├─ 단위 테스트         JUnit 5·MockMvc (BE) / vitest (FE)
  └─ 빌드 검증           ./gradlew bootJar / vite build
```

**Day 1에 gitleaks부터 붙입니다.** 시크릿은 한 번 커밋되면 히스토리에서 지우기 어렵기 때문에,
다른 어떤 스캐너보다 먼저 동작해야 합니다.

### 4.2 단계별 보안 활동

| 단계 | 활동 | 담당 |
|---|---|---|
| 설계 (Day 1) | 위협 모델링 — 시크릿 노출, IDOR, XSS 지점 식별 | 보안 챔피언 |
| 개발 | 시크릿은 환경변수로만, `.env`는 커밋 금지 | 전원 |
| PR | 보안 체크리스트 기반 리뷰 (리뷰어 1명 승인 필수) | 리뷰어 |
| CI | gitleaks · 의존성 · 정적 분석 자동 실행 | 자동 |
| 배포 (Day 5) | 운영 설정 점검 (HTTPS, 쿠키, CORS, API 키 제한) | DevOps |

### 4.3 보안 체크리스트 (PR 및 Day 5 최종 점검)

**시크릿**
- [ ] 코드·설정 파일에 API 키, 비밀번호, 클라이언트 시크릿이 없다
- [ ] `.env` 파일이 커밋되지 않았다
- [ ] Places API 키가 프론트엔드 번들에 포함되지 않았다
- [ ] 로그에 토큰·쿠키·키가 출력되지 않는다

**인증 / 인가**
- [ ] 토큰이 `localStorage` / `sessionStorage`에 없다
- [ ] 세션 쿠키에 `HttpOnly`, `Secure`, `SameSite`가 설정되었다
- [ ] 🔒 표시 엔드포인트가 미인증 요청에 401을 반환한다
- [ ] 리뷰 수정/삭제에서 서버가 작성자를 검증한다 (타인 리뷰 → 403)

**입력 / 출력**
- [ ] 모든 엔드포인트에 DTO와 Bean Validation이 적용되었다
- [ ] 리뷰 본문에 HTML sanitization이 적용되었다 (XSS)
- [ ] SQL이 ORM/파라미터 바인딩으로만 작성되었다
- [ ] 에러 응답에 스택 트레이스·내부 경로가 노출되지 않는다

**인프라**
- [ ] 운영 통신이 HTTPS로 강제된다
- [ ] CORS가 프론트엔드 오리진만 허용한다 (와일드카드 없음)
- [ ] 리뷰 작성 API에 rate limiting이 적용되었다
- [ ] Google API 키에 리퍼러/IP 제한과 API 제한이 걸려 있다

**정책 준수**
- [ ] DB에 `place_id` 외 구글 데이터 컬럼이 없다
- [ ] 위경도를 포함한 Places 응답을 캐시하지 않는다
- [ ] 지도에 Google attribution이 표시된다
- [ ] 스크래핑 코드가 없다

## 5. 협업 규칙

### 5.1 브랜치 및 머지

```
main       ← 배포 (Day 5)
 └ develop ← 통합 (매일 저녁)
    ├ feature/SGF-XX-설명
    └ fix/SGF-XX-설명
```

- `main`, `develop` **직접 push 금지** (브랜치 보호 규칙 설정)
- 머지 조건: **CI 통과 + 리뷰어 1명 승인**
- feature 브랜치는 하루를 넘기지 않는 크기로 자릅니다. 길어지면 충돌 비용이 일정을 잡아먹습니다.

### 5.2 커밋 / PR

```
SGF-12 feat: 가격대별 핀 색상 적용
SGF-15 fix: 리뷰 중복 작성 검증 누락 수정
```

- Jira 이슈 키로 시작 (자동 연동)
- 타입: `feat` `fix` `refactor` `docs` `test` `chore`
- PR 제목: `[SGF-XX] 내용`

### 5.3 일일 리듬

| 시각 | 활동 | 소요 |
|---|---|---|
| 오전 | 스탠드업 — 어제 한 일 / 오늘 할 일 / 블로커 | 10분 |
| 수시 | 블로커 발생 시 즉시 공유 (혼자 30분 이상 막히지 않기) | — |
| 저녁 | `develop` 통합 + 동작 확인 | 30분 |

### 5.4 Definition of Done

기능 하나가 "완료"되려면:

- [ ] 요구사항 ID(FR-XXX)의 동작이 구현되었다
- [ ] CI가 통과했다
- [ ] 보안 체크리스트 해당 항목을 확인했다
- [ ] API 변경 시 CLAUDE.md 6절 API 계약을 갱신했다
- [ ] 리뷰어 1명이 승인했다
- [ ] `develop`에 머지되어 통합 환경에서 동작한다

## 6. 범위 관리

### 6.1 구현하지 않을 것

즐겨찾기, 리뷰 신고, 일정 저장/공유, 학교별 필터, 구글 리뷰 텍스트 분석, 이미지 업로드, 다국어.

**요청받지 않은 기능을 임의로 추가하지 않습니다.** 아이디어는 v2 백로그에 적어두세요.

### 6.2 일정이 밀릴 때 버리는 순서

Day 4 시점에 일정이 밀렸다면 아래 순서로 축소합니다.

1. 사이드바 가격 등급 필터 (FR-306, Should 항목)
2. 예산 일정 개별 항목 교체 (FR-506) → 재생성으로 대체
3. 모바일 반응형 → 데스크톱 데모로 한정
4. 카테고리 연속 회피 로직 (FR-504) → 단순 매칭으로 대체

**절대 축소하지 않는 것**: 보안 요구사항(NFR-S)과 정책 준수(NFR-L).
이 둘은 기능이 아니라 전제 조건입니다.
