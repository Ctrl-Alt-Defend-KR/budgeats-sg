## 1. 개요

### 1.1 목적

싱가포르로 해외 연수를 온 한국 학생이 **제한된 예산 안에서 식사할 곳을 빠르게 결정**하도록 돕는다.

기존 지도 서비스의 한계:

| 문제 | BudgEats SG의 해결 |
|---|---|
| 구글 `price_level`은 0~4 등급뿐이라 실제 지출액을 알 수 없음 | 학생이 직접 입력한 **1인당 실측 가격** 축적 |
| 리뷰가 현지인/관광객 기준이라 한국인 입맛 여부를 알 수 없음 | **한국인 입맛 태그** (안 짜요, 향신료 약함 등) |
| 예산은 있는데 "며칠 동안 어떻게 나눠 쓸지" 계획이 안 섬 | **예산 기반 식사 일정 자동 생성** |

### 1.2 범위

**포함 (MVP)**: 지도·핀 표시, 가격대별 색상 구분, Google 로그인, 추천 사이드바, 자체 리뷰 CRUD, 예산 일정 생성

**제외 (v2 이후)**: 즐겨찾기, 리뷰 신고, 일정 저장/공유, 학교별 필터, 구글 리뷰 텍스트 분석, 이미지 업로드, 다국어

### 1.3 용어

| 용어 | 정의 |
|---|---|
| 자체 리뷰 | 본 서비스 사용자가 작성한 리뷰. 구글 리뷰와 무관하며 DB에 저장됨 |
| 실측 가격 | 자체 리뷰의 `price_per_person` (SGD). 사용자가 실제 지출한 1인당 금액 |
| 가격 등급 | 저가/중가/고가 3단계. 핀 색상(초록/노랑/빨강)에 대응 |
| `place_id` | Google Places가 부여한 장소 고유 식별자. **DB 저장이 허용되는 유일한 구글 데이터** |
| `price_level` | 구글이 제공하는 가격대 지표(0~4). 실측 데이터가 부족할 때 fallback으로 사용 |
| N | 실측 평균을 채택하기 위한 최소 리뷰 건수 (미확정, 잠정 3) |

## 2. 전체 설명

### 2.1 제품 관점

웹 기반 SPA. 프론트엔드와 백엔드를 **별도 서버로 분리**하여 운영한다.

```
[Browser]
   │
   ├─ Frontend (React)      → Maps JavaScript API (지도 렌더링 전용)
   │
   └─ Backend (Spring Boot) → Places API / H2 / OAuth 2.0
```

Places API 호출은 **전부 백엔드가 대행**한다. 프론트엔드에 노출되는 유일한 구글 키는
HTTP 리퍼러 제한이 걸린 지도 렌더링용 키이며, 이 키에는 Places API 권한을 부여하지 않는다.

### 2.2 사용자 특성

| 항목 | 내용 |
|---|---|
| 주 사용자 | 싱가포르 해외 연수 중인 한국 대학생 (20대 초중반) |
| 기술 수준 | 스마트폰·웹 서비스에 익숙. 별도 학습 불필요 |
| 사용 맥락 | **이동 중 모바일 브라우저**에서 즉석 검색이 다수 |
| 예산 감각 | 끼니당 5~15 SGD 수준의 지출을 민감하게 인식 |
| 언어 | 한국어 UI. 식당명·주소는 영문 원문 표기 |

### 2.3 제약사항

| ID | 제약 | 근거 |
|---|---|---|
| CON-1 | `place_id` 외 Places API 응답 데이터를 DB에 저장할 수 없다 | Google Maps Platform 약관 |
| CON-2 | 이번 MVP에서는 위경도(lat/lng)를 포함한 Places 응답을 캐시하지 않는다 | 저장 범위 최소화 |
| CON-3 | 구글 지도 페이지 스크래핑 금지 | Google Maps Platform 약관 |
| CON-4 | 구글 리뷰 텍스트를 사용·저장하지 않는다 | API가 5건만 제공, 저장 불가 |
| CON-5 | 지도 및 구글 데이터 표시 시 Google attribution 필수 | Google Maps Platform 약관 |
| CON-6 | 개발 기간 5일, 인원 4명 | 프로젝트 일정 |
| CON-7 | Places API 호출량이 곧 비용이므로 필드 마스크를 최소화한다 | 과금 정책 (SKU 등급) |

### 2.4 가정 및 의존성

- Google Cloud 프로젝트와 결제 계정이 스프린트 시작 시점에 준비되어 있다.
- 사용자는 Google 계정을 보유한다 (별도 회원가입 없음).
- 대상 지역에 Places API 데이터가 충분히 존재한다.
- 초기에는 자체 리뷰가 0건이므로, **모든 핀이 `price_level` fallback으로 표시**된다.
  서비스 가치는 리뷰 축적에 비례하여 증가한다.

## 3. 기능 요구사항

우선순위: **M** = Must (MVP 필수) / **S** = Should (여유 시)

### 3.1 인증 (FR-100)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-101 | 사용자는 Google 계정으로 로그인할 수 있다 | M |
| FR-102 | 최초 로그인 시 `google_sub`를 기준으로 사용자 레코드를 생성한다 | M |
| FR-103 | 세션은 HttpOnly + Secure 쿠키로 유지한다 | M |
| FR-104 | 로그인하지 않아도 지도·핀·추천 리스트는 조회할 수 있다 | M |
| FR-105 | 리뷰 작성 시도 시 미로그인 상태면 로그인을 유도한다 | M |
| FR-106 | 사용자는 로그아웃할 수 있으며, 로그아웃 시 세션 쿠키가 무효화된다 | M |

**FR-103 검증 기준**: 브라우저 콘솔에서 `document.cookie`로 세션 토큰이 조회되지 않고,
`localStorage` / `sessionStorage`가 비어 있어야 한다.

### 3.2 지도 및 핀 (FR-200)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-201 | 지도에 현재 보이는 영역의 식당을 핀으로 표시한다 | M |
| FR-202 | 핀 색상을 가격 등급에 따라 초록/노랑/빨강으로 구분한다 | M |
| FR-203 | 핀 클릭 시 식당 상세(이름·평점·주소·가격 등급·자체 리뷰 요약)를 표시한다 | M |
| FR-204 | 최초 진입 시 사용자의 현재 위치를 지도 중심으로 설정한다. 위치 권한 거부 시 싱가포르 중심 좌표를 사용한다 | M |
| FR-205 | 지도 이동/줌 종료 후 식당 목록을 갱신한다 | M |
| FR-206 | 지도에 Google attribution(로고)이 가려지지 않게 표시한다 | M |

**FR-202 가격 등급 산정 규칙** (CLAUDE.md 5.1절):

```
해당 place_id의 자체 리뷰가 N건 이상 →  실측 price_per_person 평균으로 등급 산정
              N건 미만 (fallback)    →  Google price_level 매핑값 사용
```

| 등급 | 색상 | 실측 1인 비용 (SGD) | `price_level` |
|---|---|---|---|
| 저가 | 🟢 초록 | ~ 8 | 0~1 |
| 중가 | 🟡 노랑 | 8 ~ 15 | 2 |
| 고가 | 🔴 빨강 | 15 ~ | 3~4 |

> 경계값(8/15)과 N은 미확정. 코드에 하드코딩하지 않고 설정값으로 분리한다 (CLAUDE.md 8절).

**FR-205 검증 기준**: 지도를 연속으로 드래그해도 API 호출이 디바운스되어,
드래그 1회당 `/places/nearby` 호출이 1건을 넘지 않아야 한다.

### 3.3 추천 사이드바 (FR-300)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-301 | 화면 우측에 현재 지도 영역의 식당 추천 리스트를 표시한다 | M |
| FR-302 | 리스트는 구글 평점 기준으로 정렬한다 | M |
| FR-303 | 각 항목에 사용자 현재 위치로부터의 거리를 표시한다 | M |
| FR-304 | 각 항목에 가격 등급을 색상으로 표시한다 | M |
| FR-305 | 항목 클릭 시 지도의 해당 핀으로 이동 및 상세를 표시한다 | M |
| FR-306 | 가격 등급으로 리스트를 필터링할 수 있다 | S |

### 3.4 자체 리뷰 (FR-400)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-401 | 지도 우측 하단 (+) 플로팅 버튼으로 리뷰 작성을 시작한다 | M |
| FR-402 | 장소 검색 팝업에서 식당을 검색·선택한다 | M |
| FR-403 | 식당 선택 시 **`place_id`만** 서버로 전송한다 | M |
| FR-404 | 리뷰 입력 항목: 평점(1~5), 1인당 가격(SGD), 본문(최대 1000자), 맛 태그, 학생 태그, 방문 유형, 재방문 의사, 익명 여부 | M |
| FR-405 | 평점·가격·본문은 필수 입력이다 | M |
| FR-406 | 한 사용자는 같은 식당에 리뷰를 1건만 작성할 수 있다 | M |
| FR-407 | 이미 리뷰를 작성한 식당을 다시 선택하면 수정 모드로 전환한다 | M |
| FR-408 | 작성자 본인만 자신의 리뷰를 수정·삭제할 수 있다 | M |
| FR-409 | 식당 상세에서 해당 식당의 자체 리뷰를 최신순으로 조회한다 | M |
| FR-410 | 익명 리뷰는 작성자 이름 대신 익명 표기를 노출한다 | M |
| FR-411 | 리뷰 저장 후 해당 식당의 실측 평균 가격을 재계산하고 핀 색상에 반영한다 | M |

**태그 항목** (미확정 — 잠정):

- **맛 태그**: 한국인 입맛 맞음 / 안 짜요 / 향신료 약함 / 매운맛 있음
- **학생 태그**: 가성비 / 양 많음 / 혼밥 가능 / 포장 가능 / 카드 결제 가능
- **방문 유형**: 혼밥 / 친구 / 단체 / 기타

**FR-403 검증 기준**: 리뷰 작성 요청의 페이로드에 식당명·주소·평점 등 구글 데이터 필드가 포함되지 않아야 한다.

**FR-408 검증 기준**: 다른 사용자의 리뷰 ID로 `PATCH`/`DELETE`를 직접 호출하면 403을 반환해야 한다
(프론트에서 버튼을 숨기는 것만으로는 충족되지 않음).

### 3.5 예산 일정 생성 (FR-500)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-501 | 사용자가 총예산(SGD), 기간(일), 하루 끼니 수를 입력한다 | M |
| FR-502 | 끼니당 예산 = 총예산 ÷ (기간 × 하루 끼니 수) 로 산출한다 | M |
| FR-503 | 끼니당 예산 범위에 맞는 가격 등급의 식당을 배정한다 | M |
| FR-504 | 동일 카테고리 식당이 연속으로 배정되지 않도록 회피한다 | M |
| FR-505 | 생성된 일정을 일자·끼니 단위 표로 출력한다 | M |
| FR-506 | 개별 항목을 같은 가격 등급의 다른 식당으로 교체할 수 있다 | M |
| FR-507 | 조건에 맞는 식당이 부족하면 사용자에게 사유를 안내한다 | M |

> 일정 **저장/공유는 MVP 범위 밖**이다. `POST /budget-plans`는 무상태로 계산 결과만 반환하며,
> `budget_plans` 테이블·엔티티를 만들지 않는다.

## 4. 외부 인터페이스 요구사항

### 4.1 사용자 인터페이스

- 기준 레이아웃: Figma 시안. **픽셀 정합보다 기능 동작을 우선**한다 (CLAUDE.md 8절).
- 기본 화면: 좌측 지도 + 우측 사이드바, 지도 우측 하단 (+) 플로팅 버튼.
- 모바일 브라우저에서 지도가 화면 전체를 차지하고 사이드바는 접히는 형태를 지원한다.

### 4.2 소프트웨어 인터페이스

| 외부 시스템 | 용도 | 호출 주체 |
|---|---|---|
| Google Maps JavaScript API | 지도 렌더링, 마커 표시 | Frontend |
| Google Places API (New) | 주변 검색, 장소 검색, 장소 상세 | **Backend 전용** |
| Google OAuth 2.0 | 사용자 인증 | Backend |
| H2 (file-backed) | 사용자·자체 리뷰 영속화 | Backend |

### 4.3 API 인터페이스

Base URL `/api/v1`. 전체 엔드포인트 목록과 응답 형식은 [CLAUDE.md 6절](../CLAUDE.md)이 원본이다.

공통 응답 형식:

```json
{ "success": true,  "data": { } }
{ "success": false, "error": { "code": "INVALID_INPUT", "message": "" } }
```

## 5. 비기능 요구사항

### 5.1 보안 (NFR-S)

| ID | 요구사항 | 검증 방법 |
|---|---|---|
| NFR-S1 | API 키·시크릿·DB 비밀번호를 코드에 하드코딩하지 않는다 | CI gitleaks 스캔 (검출 시 빌드 실패) |
| NFR-S2 | OAuth 토큰은 HttpOnly + Secure 쿠키에만 저장한다 (localStorage 금지) | 코드 리뷰 + 브라우저 검사 |
| NFR-S3 | 모든 사용자 입력을 서버에서 검증·sanitize한다 (XSS 방지) | Bean Validation DTO + 수동 페이로드 테스트 |
| NFR-S4 | 리뷰 수정/삭제 시 서버에서 작성자를 검증한다 (IDOR 방지) | 타 사용자 리뷰 ID로 직접 호출 → 403 확인 |
| NFR-S5 | 모든 통신에 HTTPS를 강제한다 | 배포 설정 확인 |
| NFR-S6 | 리뷰 작성 API에 사용자별 rate limiting을 적용한다 | 반복 호출 테스트 |
| NFR-S7 | SQL은 ORM/파라미터 바인딩으로만 작성한다 (SQL Injection 방지) | 코드 리뷰 |
| NFR-S8 | 로그·에러 응답에 시크릿·토큰·쿠키 값을 남기지 않는다 | 코드 리뷰 |
| NFR-S9 | 의존성 취약점 스캔을 CI에서 수행한다 | GitHub Actions |
| NFR-S10 | CORS는 프론트엔드 오리진만 허용한다 (와일드카드 금지) | 설정 확인 |

## 6. 데이터 요구사항

테이블 정의(`users`, `reviews`)의 원본은 [CLAUDE.md 4절](../CLAUDE.md)이다. 예산 일정은 저장하지 않는다.

### 6.1 저장 정책

| 데이터 | 저장 | 근거 |
|---|---|---|
| `place_id` | ✅ 영구 저장 | 약관상 허용. 자체 리뷰의 연결 키 |
| 위경도 (lat/lng) | ❌ 캐싱 안 함 | Places 실시간 조회 원칙 |
| 식당명·주소·평점·사진·영업시간 | ❌ 저장 금지 | 약관 위반. 매 요청 실시간 조회 |
| 구글 리뷰 텍스트 | ❌ 사용 안 함 | 약관 및 데이터 한계 |
| 자체 리뷰 전체 | ✅ 영구 저장 | 자체 생성 데이터 |

### 6.2 무결성 제약

- `users.google_sub` — UNIQUE
- `reviews(user_id, place_id)` — UNIQUE (동일 식당 리뷰 1건, 수정 허용)
- `reviews.rating` — 1~5
- `reviews.price_per_person` — 양수
- `reviews.content` — 최대 1000자
- `reviews.user_id` → `users.id` FK

### 6.3 개인정보

- 수집 항목은 `google_sub`, `display_name`으로 최소화한다. 이메일·프로필 사진은 저장하지 않는다.
- 익명 리뷰(`is_anonymous = true`)는 API 응답에서 작성자 이름을 제외한다
  (**프론트에서 숨기는 방식이 아니라 서버 응답 자체에서 제외**).

## 부록 A. 인수 기준 요약

MVP 완료 판정 체크리스트. Day 5 데모 전에 전 항목을 확인한다.

- [ ] 지도에 주변 식당 핀이 표시되고, 색상이 가격 등급과 일치한다
- [ ] 자체 리뷰가 N건 이상인 식당은 실측 평균 기준 색상으로 표시된다
- [ ] Google 로그인 → 리뷰 작성 → 핀 색상 갱신까지 한 흐름이 동작한다
- [ ] 같은 식당에 두 번째 리뷰를 작성하려 하면 수정 모드로 전환된다
- [ ] 타 사용자의 리뷰를 API로 직접 수정·삭제하면 403이 반환된다
- [ ] 브라우저 저장소에 토큰이 남아 있지 않다
- [ ] DB에 식당명·주소·평점이 저장된 컬럼이 없다
- [ ] 지도에 Google attribution이 표시된다
- [ ] 예산 입력 시 일정표가 생성되고 개별 항목을 교체할 수 있다
- [ ] CI(gitleaks, 의존성 스캔, 테스트)가 통과한다
